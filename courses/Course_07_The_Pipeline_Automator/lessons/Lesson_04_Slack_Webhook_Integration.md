# Lesson 4: Slack Webhook Integration

## The problem

It is 13:00 Tuesday. The router script from Lesson 3 can determine severity and branch to the right handler. But the handlers do not exist yet. When the router calls hooks/slack-notify.py for an Anomaly, it fails with "file not found." When it calls hooks/escalation-email.py for a Critical finding, the same thing happens. The wiring is in place, but the endpoints are missing. Your VP wants Slack notifications for anomalies by end of day, and email escalation for critical findings by tomorrow.

At Ironclad Procurement Group, the procurement-alerts Slack channel is where the analytics team monitors real-time updates. An anomaly alert needs to land there with enough context for someone to act: which supplier, which transaction, how large the amount, and how many times the daily average. For critical findings, an email draft goes to the VP and the category manager with the full summary and recommended actions.

## What Claude Code does for you

You will create two Python scripts: hooks/slack-notify.py (for Anomaly and Critical alerts) and hooks/escalation-email.py (for Critical alerts only). The Slack script extracts the anomaly table from the monitor file, builds a Slack Block Kit JSON payload, and saves it to notifications/slack-messages/. The email script extracts the summary and recommended actions, then saves a structured email draft to notifications/email-drafts/.

## Setup

1. Lessons 1 through 3 complete.
2. The router script hooks/session-complete-hook.sh working.
3. Python 3.10 or later installed.
4. The sample monitor files in outputs/daily-monitors/.

**Step 2.** Ask Claude to create the Slack notification script.

```

4. Build a Slack Block Kit payload with a header block showing severity, a section block with the date and anomaly count, one section block per anomaly row, and a context block with the source file name.

```

You should see Claude create hooks/slack-notify.py.

**Step 3.** Review the Slack Block Kit payload structure. The JSON output should follow this shape:

```json
{
  "blocks": [
    {
      "type": "header",
      "text": {
        "type": "plain_text",
        "text": ":warning: Spend Monitor Alert: Anomaly"
      }
    },
    {
      "type": "section",
      "text": {
        "type": "mrkdwn",
        "text": "*Date:* 2026-04-21\n*Anomalies detected:* 3"
      }
    },
    {
      "type": "section",
      "text": {
        "type": "mrkdwn",
        "text": "*Apex Electronics*\nTransaction: TXN007842 | Amount: $42,800.00 | Multiple: 6.5x daily avg"
      }
    },
    {
      "type": "divider"
    },
    {
      "type": "context",
      "elements": [
        {
          "type": "mrkdwn",
          "text": "Source: monitor-2026-04-21.md | Generated by Claude Code"
        }
      ]
    }
  ]
}
```

The header uses `:warning:` for Anomaly and `:rotating_light:` for Critical. Each anomaly row gets its own section block with the supplier name in bold, the transaction ID, the dollar amount, and the multiple.

## Common mistakes and how to recover

- **Symptom:** The Slack payload has zero anomaly rows even though the monitor file lists three. **Fix:** Check the regex pattern in the script. The pattern must match the exact markdown table format, including the pipe characters and dollar signs. Test the pattern against the raw file content.
- **Symptom:** The JSON file is malformed (missing braces or extra commas). **Fix:** Use `json.dump()` with `indent=2` to write the file. Do not build JSON by hand with string concatenation. Let the json library handle formatting.
- **Symptom:** The email draft is missing the recommended actions. **Fix:** The extraction regex must match the `## Recommended Actions` section header exactly. Check for extra spaces or different capitalization in the monitor file.
- **Symptom:** The script fails with `ModuleNotFoundError`. **Fix:** The scripts use only standard library modules (json, os, re, sys, pathlib, datetime). No pip install is needed. If you see this error, check that Python 3.10 or later is on your PATH.
- **Symptom:** The Slack payload does not include audit context (source file name and generation method). **Fix:** Add a context block at the end of the blocks list. This block should name the source file and note that it was generated by Claude Code. Auditors need this trail.
- **Symptom:** You created separate Slack scripts for Anomaly and Critical. **Fix:** One script handles both. The router calls slack-notify.py for Anomaly and for Critical. The script adapts the emoji (`:warning:` vs. `:rotating_light:`) based on the severity it extracts from the file.
